# Server-side language bridge evidence

User reports: mixed Arabic/English project records after clicking native taxonomy filters; some terms missing. Stack identified: Polylang + LiteSpeed Cache. Live URL supplied: https://syncs.com.sa/project/. The user reports the issue persists with LiteSpeed's supported before_optm comparison URL. This does not rule out every cache layer and is not a trace of the actual AJAX/REST response.

The implementation registers only elementor/query/syncs_projects_ar and elementor/query/syncs_projects_en plus admin settings/menu hooks. Each ID selects a registered, admin-configurable Polylang slug. It sets WP_Query post_type=project, lang=<selected slug>, suppress_filters=false; native tax_query, inclusion rules, page size/order/pagination and cache_results stay unchanged. It does not infer language from cookies, GET lang, or pll_current_language. Missing required configuration returns post__in=[0] for these reserved query IDs only. No global query hooks or SQL rewrites are registered.

Admin mappings are capability protected via manage_options and WordPress Settings API/options.php nonce checks. Candidate slugs are sanitized/whitelisted against registered languages; identical language selections are rejected. No content-language assignment, translation creation, cache purge or cache-setting write is performed. The setup requires the user to enter each Query ID in the correct translated Elementor document; the ZIP does not edit page/template conditions or Elementor document IDs automatically.

Executed: PHP syntax and contract simulation under @php-wasm/cli 3.1.58 on PHP 7.4, 8.3 and 8.5. Nine CLI invocations completed with exit 0. See validation/results.json. Tests simulate public WordPress hooks and Polylang APIs and deliberately present a conflicting request/cookie language. They are not a running WordPress database or native Pro filter request. Live staging installation, native custom-query execution during taxonomy AJAX/REST, actual Polylang SQL, term-language assignment, Elementor template translation, and cache behavior remain unverified.

Official Polylang public APIs and language query handling reviewed at commit a42fe0c741c9aec32439b7e42e204e867b9d2b51: src/api.php, src/query.php, src/frontend/choose-lang.php. Official LiteSpeed optimization bypass/flags reviewed at commit a4bd5fa11b77c95c660f003aec6a6c0d982cc9a8: src/core.cls.php and src/optimize.cls.php. Elementor Query ID hook is the documented public contract at https://developers.elementor.com/docs/hooks/custom-query-filter/; that documentation host could not be fetched by this environment, and the actual installed Pro runtime was not inspected.

This is a reviewable scoped integration, pending staging verification. It is not presented as a deployed or certified fix for the entire site. An inaccessible live server and absent Pro/runtime traces prevent a final root-cause or success claim.
