# قسم محتوى الخدمة — نفس شكل الكروت السابق بدون أزرار فلترة

## اختاري ملف السكشن

| المحتوى المطلوب | عربي | إنجليزي |
| --- | --- | --- |
| مشاريع | SYNCs-Service-Projects-AR.json | SYNCs-Service-Projects-EN.json |
| مقالات | SYNCs-Service-Articles-AR.json | SYNCs-Service-Articles-EN.json |

ملف `SYNCs-Service-Card.json` هو بطاقة Loop Item عامة: Featured Image للصورة، Post Title للعنوان، Post URL للرابط. الصورة ليست ثابتة؛ Elementor يستبدل بيانات المعاينة ببيانات كل مشروع/مقال في نتيجة الاستعلام.

## التركيب مرة واحدة لكل سكشن خدمة

1. استخدمي صفحة تجريبية واحتفظي بنسخة من السكشن الحالي. من Templates → Saved Templates → Import Templates استوردي البطاقة `SYNCs-Service-Card.json`، ثم ملف السكشن المناسب من الجدول. الحزمة ZIP للتنزيل؛ استيراد Elementor يتم لملفات JSON الموجودة داخلها.
2. أدرجي السكشن داخل صفحة الخدمة مكان القسم القديم. من Navigator اختاري Loop Grid، وفي اختيار Template حددي **SYNCs — Service content card (dynamic Post URL)**. رقم البطاقة الجديد يحدده WordPress عند الاستيراد؛ لا يُفترض أن يكون 6526. رقم 6526 محفوظ في ملفات السكشن كمرجع بطاقتك الأصلية على نفس الموقع إلى أن تختاري البطاقة الجديدة. للمقالات يلزم اختيار البطاقة العامة حتى يكون الرابط Post URL ويعمل دون حقل ACF project_url.
3. من Loop Grid → Query اختاري مصدر المحتوى المناسب: Projects للمشاريع أو Posts للمقالات. الملف المختار يحمل نوع المحتوى بالفعل (`project` أو `post`)؛ راجعي الاسم المعروض في نسختك من Elementor.
4. من Query → Include By اختاري **Term**، ثم من اختيار المصطلحات حددي **قسم الخدمة** الذي يحتوي المحتوى المطلوب. للمشاريع اختاري القسم الصحيح من تصنيف المشاريع الموجود عندك (`project_category` في التصدير الأصلي)، وللمقالات اختاري القسم من تصنيفات المقالات الفعلية. لا توجد أرقام أقسام مفترضة داخل JSON لأن أسماء/IDs خدماتك لم تُرسل.
5. اختاري ترتيب التاريخ من الأحدث للأقدم إذا كان المطلوب إظهار المنشور الجديد أولًا. أي مشروع/مقال جديد منشور ومسند لنفس القسم يصبح مؤهلًا للظهور دون إضافته يدويًا للسكشن، وفق حد النتائج والترتيب والكاش. لا تستخدمي قائمة محتوى يدوية إذا أردتِ هذا السلوك.
6. عدّلي عنوان السكشن من Heading widgets. الصورة والعنوان والرابط داخل البطاقة native ويمكن تعديل Dynamic Tags من قالب Loop Item. الكروت والحركة متنسقة عبر HTML widget المرفق. أبقي الكلاسات كما هي إذا أردتِ نفس الشكل.
7. احفظي، وراجعي الواجهة الأمامية، وامسحي كاش رابط الخدمة من LiteSpeed بعد تغيير الإعدادات ليصل الكود/الاستعلام الجديد للزائر. إصدار العربية والإنجليزية يختار نصوص واتجاه السكشن فقط؛ لغة بيانات المشاريع تعتمد على إعدادات Polylang الصحيحة وتعيين لغات المحتوى والأقسام، مع اختيار مصطلح الخدمة المترجم الصحيح لكل صفحة.

**النتيجة للزائر:** عنوان وكروت وصور وعناوين وروابط، مع أسهم للتنقل بين الكروت. لا يوجد Taxonomy Filter widget ولا أزرار أقسام ولا طلب AJAX لتغيير القسم. اختيار قسم الخدمة يتم خلف الكواليس في Query مرة واحدة لكل سكشن.

## نطاق الربط والتحديث

- الكروت ديناميكية؛ مصدر البيانات WordPress وLoop Grid الحقيقي، وليس صورًا أو قائمة منشورات مكتوبة داخل HTML.
- علاقة السكشن بالخدمة محددة بالقسم الذي تختارينه في Query. لا يستنتج JSON قسم الخدمة من URL تلقائيًا. إذا كان قالب Elementor واحدًا يُطبّق على كل الخدمات، فاختيار Term ثابت داخل القالب يظل ثابتًا؛ الربط بسياق الخدمة الحالية في قالب مشترك يحتاج علاقة/حقل الخدمة الفعلي قبل إعداد استعلام سياقي.
- حد النتائج محفوظ من ملفك الأصلي: 30. يمكن تقليله أو ضبط الترقيم من Elementor. الأسهم تتنقل بين العناصر المحمّلة فقط ولا تجلب صفحات استعلام إضافية.
- المقالات والمشاريع في ملفات منفصلة لأن لكل مصدر استعلامًا وتصنيفاته. يمكن إدراج القسمين معًا إذا أردتِ؛ IDs ملفات النسخ مختلفة، والمتحكم يعزل كل سكشن.
- البطاقة الجديدة تستخدم رابط المنشور نفسه بدل ACF project_url. راجعي هذا الاختيار إذا كانت روابط مشاريعك الأصلية مقصودة كروابط خارجية مخصصة.
- Query ID فارغ في الملفات الجديدة. لا تتطلب إزالة أزرار الفلترة إضافة PHP. أي Query ID مخصص يفرض نوع project يحتاج مراجعة قبل استخدامه في قسم مقالات مصدره post.

## التوافق والاختبار

هذه قوالب محفوظة مبنية على تصديرك الحقيقي للـLoop Grid وLoop Item، مع إضافة رابط Post URL الأصلي في Elementor Pro. لا توجد تجربة استيراد داخل WordPress في هذه البيئة. اختبري الاستيراد، اختيار البطاقة والقسم، لغة النتائج، إضافة منشور جديد، الروابط، ثم إعادة فتح القالب في المحرر على staging قبل اعتماد التوافق. معاينات preview وvalidation تستخدم رسومات وبيانات تجريبية لا تدخل في استعلام القالب الفعلي.
