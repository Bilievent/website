# QA — service content sections without taxonomy UI

Baseline inspected: repository AGENTS.md and all four local Elementor skills; the previously generated full page/card derived from user exports #6818 and #6526. Native loop-grid source settings and container/loop-item document structures are retained.

Static validator passes for four section variants and one card: unique seven-character IDs per document; one real loop-grid in each section; no taxonomy-filter widget; no H1 added by a service section; source post type project or post; 30-result cap retained; native masonry disabled; custom Query ID absent; embedded CSS/JS match source copies. Card bindings are native Featured Image, Post Title and Post URL with H3 titles, without ACF URL dependency. Source preview/fallback media metadata is not a hardcoded slide list. Section variants have distinct widget IDs for safe composition in one page.

The CSS/controller use a distinct service-specific scope and registry so they do not mount an old projects-page controller on these sections. All former taxonomy-filter selectors are removed. Native Elementor query/backend language/caching ownership is unchanged. No term ID is inserted because actual service-category IDs were not supplied. The native Query Include By Term step is required before a section is service-specific. For a single shared service template, fixed Term selection does not infer the current service; its actual relationship schema would be required for that separate query setup.

See validation/browser-results.json for completed outcomes. The Chromium/Playwright harness renders native-style wrappers from actual JSON with simulated WordPress records. It checks Projects/Articles × EN/AR × 1440/768/390px (12 cases), absence of taxonomy/filter UI, no document horizontal overflow, active-card proportions, controls and localized labels. Additional checks cover empty/single/new result sets, native link preservation, RTL keyboard and reduced motion. Desktop and mobile screenshots were visually inspected. Fixtures are original abstract test artwork and are not native media content in the delivered section.

Not executed: actual WordPress/Elementor import; new Loop Item ID selection; native Pro Post URL resolution; native Query category selection; real site/service contextual query; Polylang content language; caching after content publishing; editor reopening and export/re-import; real touch and assistive technology. Prior source-site access was blocked by the environment network proxy, and no credentials/runtime access were supplied. The deliverable remains a saved-template prototype pending staging tests, not an official Website Kit or a deployed site change.
