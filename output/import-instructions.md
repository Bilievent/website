# Import into Elementor Pro

This is a saved-section template prototype and companion files, not an official Elementor Website Kit. Import the JSON, not the companion ZIP, through Saved Templates. No full-site settings or existing content are replaced.

1. Back up the site and use staging. Record WordPress, Elementor, Elementor Pro, theme and active add-on versions. Enable Elementor Containers if needed. Export an existing working Container template as the installation-specific baseline.
2. Unzip the companion bundle locally. Upload your four real project photographs to WordPress Media Library. The four assets/demo-project-*.jpg files are optional original demo artwork, not actual SYNCs projects. Ordinary WordPress uploads do not automatically use the placeholder /uploads/syncs-projects/ paths in the JSON.
3. In WordPress, use Templates > Saved Templates > Import Templates (labels can differ by Elementor version). Choose templates/syncs-selected-projects.json. Import as a saved Container template. If Elementor requests permission to import unfiltered content, have an authorized administrator review the HTML widget's CSS and JavaScript before proceeding. Do not weaken site security settings globally.
4. Open a staging page with Elementor. Insert the saved template using the folder/library icon. Use the Navigator to locate all four sx-card Containers. Select each Image widget and choose its photograph from Media Library; this is REQUIRED because packaged image URLs are deliberate placeholders and do not exist on your website. Set Media Library alt text and select Full image size. Cards crop images using object-fit: cover.
5. Edit the eyebrow, H2, category paragraphs and four H3 project titles directly in their native Heading widgets. Edit the native Button text and replace its temporary #syncs-projects destination with your real projects page URL. Project cards currently have no links; add a destination to each H3 Heading's Link field if required.
6. The HTML widget contains scoped styling, carousel controls, and a small controller. Edit --sx-bg and --sx-accent there for brand colors. Keep the syncs-projects, sx-track, sx-card and sx-active class names. Do not remove the HTML widget: it supplies the layout and interaction. Companion assets/section.css and assets/controller.js are copies for review, not extra files you must enqueue. Do not load those copies a second time.
7. Save on staging, regenerate Elementor CSS/data if needed, and clear relevant caches. Exclude this controller from script deferral/minification if an optimizer breaks it. Confirm the logged-out frontend; editor preview alone is insufficient. Some role, hosting, CSP, or security configurations strip/block inline scripts: have your developer move the reviewed controller to an approved enqueue mechanism if that occurs.
8. Verify at 1440, 768 and 390px, plus your theme's custom breakpoints: images load, titles remain readable, no page overflow, previous/next works, mobile swipe works, keyboard controls work, links have correct destinations, reduced motion is honored. Reopen in Elementor and confirm every image/text/button remains editable. Export/re-import from that same installation to validate compatibility.

Only after those checks should you use the section on your live page. No production changes have been made. For multiple copies on one page, assign unique CSS IDs and update each CTA anchor; scoped classes/controller support independent instances but duplicate IDs should be avoided.

If import fails, provide the installed version numbers, exact error, and a known-good Container template JSON export. No administrator password is needed in chat.
